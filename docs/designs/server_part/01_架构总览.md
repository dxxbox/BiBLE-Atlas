# FastAPI 架构总览（v3）

本文档概述基于 FastAPI 的文档搜索系统架构设计。

---

## 架构原则

### 1. 功能垂直聚合 + API 水平聚合

```
✅ 推荐架构：
features/               # 功能垂直聚合（业务逻辑）
├── search/            # 搜索功能（完整的业务单元）
│   ├── service.py
│   ├── repositories/
│   └── schemas.py
└── upload/            # 上传功能
    ├── service.py
    └── schemas.py

app/api/               # API 水平聚合（对外接口）
├── v1/
│   ├── search.py
│   ├── upload.py
│   └── docs.py
└── deps.py
```

**优势**：
- 业务逻辑内聚，易于理解和维护
- 团队可以按功能分工
- API 版本管理清晰
- 测试更简单

## 分层职责

### 1. API 层（app/api/）

**职责**：
- 定义 HTTP 端点
- 参数验证（Request 模型）
- 调用 Service 层
- 返回 Response

**不应包含**：
- 业务逻辑
- 数据库操作
- 复杂计算

### 2. Service 层（features/*/service.py）

**职责**：
- 实现业务逻辑
- 编排多个 Repository
- 数据转换和聚合
- 错误处理

**不应包含**：
- HTTP 相关代码
- 直接的数据库操作

### 3. Repository 层（features/*/repository.py）

**职责**：
- 数据访问抽象
- ES/Redis 操作
- 查询构建
- 结果映射

**不应包含**：
- 业务逻辑
- HTTP 相关代码

### 4. Infrastructure 层（infrastructure/）

**职责**：
- 提供基础设施客户端
- 工具类（向量生成、重排序）
- 第三方服务封装

## 核心设计模式

### 1. 多仓储模式（Repository Pattern）

不同文档类型使用不同的 Repository：

```python
# features/search/repositories/
├── base.py          # BaseSearchRepository（通用逻辑）
├── factory.py       # SearchRepositoryFactory（选择仓储）
├── code.py          # CodeSearchRepository（CODE 特定逻辑）
├── sct.py           # SctSearchRepository（SCT 特定逻辑）
└── skill.py         # SkillSearchRepository（SKILL 特定逻辑）
```

**优势**：
- 每个 Repository 职责单一
- 易于扩展新文档类型
- 索引映射和查询逻辑分离

### 2. 工厂模式（Factory Pattern）

根据文档类型动态选择 Repository：

```python
repository = SearchRepositoryFactory.create(
    doc_type="CODE",
    es_client=es
)
```

### 3. 依赖注入（Dependency Injection）

使用 FastAPI 的依赖注入系统：

```python
@router.post("/search")
async def search(
    request: SearchRequest,
    service: SearchService = Depends(get_search_service)
):
    return await service.search(request)
```

## 数据流

### 搜索请求流程

```
1. 客户端请求
   POST /api/v1/search
   {
     "keyword": "async",
     "doc_type": "CODE",
     "index": "test_feng"
   }
   
2. API 层（app/api/v1/search_api.py）
   - 验证请求参数（SearchRequest）
   - 调用 SearchService
   
3. Service 层（features/search/search_service.py）
   - 根据 doc_type 从工厂获取 Repository
   - 调用 Repository.search()
   - 聚合结果
   
4. Repository 层（features/search/repositories/code.py）
   - 从配置读取索引映射
   - 构建 ES 查询 DSL
   - 执行查询
   - 返回结果
   
5. 响应
   {
     "results": [...],
     "total": 100,
     "took": 23
   }
```

### 文档下载流程

```
1. 客户端请求（单文件下载）
   GET /api/v1/download/{document_id}
   
2. API 层（app/api/v1/download_api.py）
   - 验证 document_id 格式
   - 调用 DownloadService
   
3. Service 层（features/download/download_service.py）
   - 调用 Repository.get_document()
   - 验证文件存在性
   - 设置响应头（Content-Disposition、文件名等）
   
4. Repository 层（features/download/download_repository.py）
   - 查询数据库获取文档元数据
   - 从存储层读取文件（本地/MinIO/S3）
   - 返回文件流
   
5. 响应（StreamingResponse）
   - Content-Type: application/octet-stream
   - Content-Disposition: attachment; filename="xxx.md"
   - X-File-Hash: sha256_hash
```

### 批量下载流程（ZIP）

```
1. 客户端请求
   POST /api/v1/download/batch
   {
     "document_ids": ["id1", "id2", "id3"],
     "package_name": "my_docs.zip",
     "include_metadata": true
   }
   
2. API 层（app/api/v1/download_api.py）
   - 验证 document_ids（最多50个）
   - 调用 DownloadService
   
3. Service 层（features/download/download_service.py）
   - 批量查询文档元数据
   - 检查文件存在性
   - 调用 ZipBuilder 构建 ZIP
   
4. ZipBuilder（features/download/zip_builder.py）
   - 创建内存 ZIP 归档
   - 逐个添加文件到 ZIP
   - 可选：添加 metadata.json
   - 返回 ZIP 字节流
   
5. 响应（StreamingResponse）
   - Content-Type: application/zip
   - X-Files-Count: 3
   - X-Zip-Method: deflate
```

## 应用启动流程

```python
# main.py
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 1. 加载静态配置
    settings = get_settings()
    
    # 2. 初始化统一的动态配置管理器
    init_config_manager(settings.config_path)
    
    # 3. 初始化数据库（根据配置选择 ES/PG/OpenSearch）
    db_type = settings.database_type  # 'elasticsearch' / 'postgres' / 'opensearch'
    
    if db_type == 'elasticsearch':
        await init_es_client()
    elif db_type == 'postgres':
        await init_pg_client()
    elif db_type == 'opensearch':
        await init_opensearch_client()
    
    # 4. 初始化 Redis 客户端（可选）
    redis_available = False
    if settings.redis_enabled:
        redis_available = await init_redis_client()
    
    # 5. 初始化 Celery（自动降级）
    # Redis 可用时使用 Redis broker，不可用时降级为 Memory broker
    await init_celery_app(use_memory_broker=not redis_available)
    
    # 6. 初始化向量工具（后台异步加载）
    # Celery 总是可用（Redis broker 或 Memory broker），因此总是异步加载
    config = get_config_manager()
    if config.get("vector_models.load_on_startup"):
        load_vector_models_task.delay()
    
    # 7. 初始化 Rerank 工具（后台异步加载）
    if config.get("rerank.enable") and config.get("rerank.preload_on_startup"):
        load_rerank_models_task.delay()
    
    yield
    
    # 清理资源
    if db_type == 'elasticsearch':
        await close_es_client()
    elif db_type == 'postgres':
        await close_pg_client()
    elif db_type == 'opensearch':
        await close_opensearch_client()
    
    if settings.redis_enabled:
        await close_redis_client()
```

**关键特性**：
- ✅ **数据库方案可选**：支持 Elasticsearch、PostgreSQL+pgvector、OpenSearch
- ✅ **Redis 可选**：不使用 Redis 时，系统仍可正常启动（异步任务功能不可用）
- ✅ **后台模型加载**：使用 Celery 后台加载模型，不阻塞系统启动
- ✅ **模型懒加载**：可配置为首次使用时才加载模型
- ✅ **优雅降级**：组件失败时记录日志但允许系统继续启动（视配置而定）

**模型存储位置**：
- **默认位置**：`~/.cache/huggingface/`（Hugging Face 默认缓存目录）
- **自定义位置**：可通过环境变量 `TRANSFORMERS_CACHE` 或 `HF_HOME` 配置
- **推荐生产环境**：`/app/models/` 或 `/data/models/`（持久化存储）

```python
# features/search/repositories/new_type.py
class NewTypeSearchRepository(BaseSearchRepository):

    def build_query(self, keyword: str, **filters) -> Dict:
        # 实现查询逻辑
        pass
```

3. 注册到工厂：
```python
SearchRepositoryFactory.register("NEW_TYPE", NewTypeSearchRepository)
```

所有存储实现都遵循统一的 `StorageBackend` 接口：
```python
# infrastructure/storage/base.py
class StorageBackend(ABC):
    @abstractmethod
    async def save_file(self, path: str, content: bytes) -> str:
        """保存文件，返回存储路径"""
        pass
    
    @abstractmethod
    async def get_file(self, path: str) -> bytes:
        """读取文件内容"""
        pass
    
    @abstractmethod
    async def delete_file(self, path: str) -> bool:
        """删除文件"""
        pass
    
    @abstractmethod
    async def file_exists(self, path: str) -> bool:
        """检查文件是否存在"""
        pass
```

**完成！** 切换存储方式只需修改配置，无需改代码。

## 总结

### 架构优势

| 方面 | 优势 |
|------|------|
| **清晰分层** | API/Service/Repository 职责明确 |
| **功能内聚** | 按功能垂直聚合，易于维护 |
| **易于扩展** | 工厂模式 + 多仓储设计 |
| **统一配置** | 一个配置文件，一个管理器 |
| **类型安全** | Pydantic 模型验证 |
| **异步高效** | 全异步架构 |
| **存储灵活** | 支持本地/MinIO/S3多种存储后端 |
| **文件管理** | session/skill大文档分块索引+原文下载 |
| **数据库可选** | 支持 ES/PG/OpenSearch 三种数据库方案 |
| **后台加载** | Celery 后台加载模型，不阻塞启动 |
| **优雅降级** | Redis 可选，不启用时系统仍可启动 |

### 核心设计决策

1. ✅ **功能垂直聚合**：业务逻辑按功能组织
2. ✅ **API 水平聚合**：对外接口统一管理
3. ✅ **多仓储模式**：不同文档类型独立处理
4. ✅ **统一配置管理**：所有动态配置在一个文件中
5. ✅ **依赖注入**：使用 FastAPI 的 DI 系统
6. ✅ **工厂模式**：动态选择实现类
7. ✅ **存储抽象**：统一接口支持多种存储后端
8. ✅ **流式响应**：大文件下载使用 StreamingResponse
9. ✅ **数据库抽象**：支持 Elasticsearch、PostgreSQL+pgvector、OpenSearch
10. ✅ **后台任务**：使用 Celery 异步处理耗时操作（模型加载、文档导入）
11. ✅ **组件可选**：Redis 和 Celery 为可选组件，不影响核心功能

### 下载功能特色

- **单文件下载**：直接通过 document_id 下载原始文件
- **批量下载**：支持多文件自动打包为 ZIP
- **按条件下载**：根据 doc_type 和 query 批量下载匹配文档
- **文件完整性**：响应头包含 SHA256 哈希值
- **元数据支持**：ZIP包可包含 metadata.json
- **多存储支持**：本地文件系统、MinIO、AWS S3 灵活切换
- **性能优化**：流式传输，避免内存溢出

### 模型管理特色

- **后台加载**：使用 Celery 在后台加载模型，应用可快速启动
- **懒加载支持**：可配置为首次使用时才加载模型
- **模型缓存**：支持 Hugging Face 默认缓存或自定义路径
- **预热机制**：启动时可选择预热模型推理
- **多模型支持**：同时支持向量模型和 Rerank 模型
- **独立进程**：模型加载在 Celery Worker 中执行，不阻塞 API 服务
