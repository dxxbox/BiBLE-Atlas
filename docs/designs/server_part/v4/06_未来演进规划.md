# v4 未来演进规划

本文档描述三个演进点：

1. **解析脚本目录统一化**
2. **Download by-search 异步导出**
3. **AI 命中缓存（Prompt/结果复用）**

---

## 演进点：解析脚本目录统一化

### 当前基线

当前设计按业务域维护脚本目录：

- `app/features/import/knowledge_base_import/parsers/`
- `app/features/import/skill_import/parsers/`
- `app/features/import/memory_import/parsers/`

脚本选择规则（当前）：

1. 请求携带 `parser_script`：保存到对应域 `parsers/` 后使用
2. 未携带：在对应域 `parsers/` 查找 `parse_{tag}.py`
3. 未命中：回退到对应域 `parsers/parse_default.py`

### 未来目标

把三域脚本目录收敛为一个统一目录，通过配置文件中的单一参数控制。

配置示例（未来）：

```yaml
parser_repository:
  parser_dir: /app/parsers
```

说明：

- 只有 `parser_dir`，没有 `directories`
- 只有 `parser_dir`，没有 `upload_save_dir`
- 上传脚本保存和脚本查找都在同一个 `parser_dir` 中完成

### 未来流程（统一目录）

1. 若请求携带 `parser_script`
   - 保存到 `parser_dir`
   - 作为本次导入最终脚本
2. 若请求未携带 `parser_script`
   - 在 `parser_dir` 查找 `parse_{tag}.py`
3. 若仍未找到
   - 在 `parser_dir` 查找 `parse_default.py`
4. 若默认脚本也不存在
   - 返回 `PARSER_SCRIPT_NOT_FOUND`

### 迁移策略

1. 兼容阶段
   - 保留当前三域目录
   - 同时支持统一 `parser_dir`
2. 收敛阶段
   - 全量迁移脚本到统一目录
   - 三域目录只保留兼容壳或移除

### 验收标准

- 三域导入 API 无需变更
- 修改 `parser_dir` 即可切换脚本来源目录
- 上传保存、脚本查找、默认回退都在同一目录完成
- `parser_script_source` 可用于审计命中来源

## 演进点：Download by-search 异步导出

### 当前基线

当前 v4 Download 定稿范围：

- 仅支持 `SKILL/MEMORY`
- 单文件下载与批量下载都走异步任务（`download.*`）
- 客户端通过 `task_id` 查询状态，完成后拉取 artifact
- 不包含按检索条件直接导出（`by-search`）

### 未来目标

新增按检索条件导出的异步接口（by-search），用于“先检索后打包”的一体化离线导出。

建议路径（未来）：

- `POST /api/download/skill/by-search`
- `POST /api/download/memory/by-search`

### 未来流程（by-search）

1. API 校验请求参数并提交 `download.{domain}.by_search` 任务
2. Worker 根据 `tag` 读取绑定（`kb_index + search_profile`）
3. 按检索参数执行查询，得到命中文档及 `related_storage_paths`
4. 去重、配额校验后构建打包清单
5. 生成 ZIP artifact 并写入任务 `result`
6. 客户端通过 artifact 拉取接口下载

### 迁移策略

1. 兼容阶段
   - 保持现有 `file/batch` 接口不变
   - 新增 `by-search` 作为独立可选能力
2. 稳定阶段
   - 增加查询分页与导出上限治理
   - 增加导出审计与成本统计

### 验收标准

- `by-search` 不改变现有 `file/batch` 契约
- 导出任务全程异步，API 仍返回 `202 + task_id`
- 支持按域复用同一导出框架（SKILL/MEMORY）
- 导出结果可复用现有 artifact 拉取与过期清理机制

## 演进点：AI 命中缓存（Prompt/结果复用）

### 当前基线

当前设计在重复请求场景下仍会重复执行模型推理或重复构建导出产物，尚未形成统一的命中缓存能力：

- 已有异步任务与会话管理，但缺少“输入相同即复用结果”的机制
- 成本统计以任务结果为主，缺少输入消耗与缓存命中维度
- 对高重复请求场景，响应时延与资源消耗仍有优化空间

### 未来目标

引入统一命中缓存机制，在不改变现有业务契约的前提下，实现可复用、可观测、可治理的 AI 调用优化能力。

核心目标：

- 相同输入特征优先复用已有结果，减少重复模型调用
- 稳定上下文支持缓存读取，降低输入消耗
- 命中效果可量化，支撑成本治理与容量规划

### 未来流程（命中缓存）

1. 请求进入后先计算缓存键（由模型配置、提示词版本、输入摘要等组成）
2. 查询缓存记录
   - 命中：直接返回缓存结果，或复用已有异步任务结果
   - 未命中：进入现有执行流程
3. 执行完成后写入缓存，并记录失效时间与来源元信息
4. 响应返回时附带缓存状态（命中/未命中）及可选统计信息
5. 定时执行过期清理与审计汇总

### 迁移策略

1. 观测先行阶段
   - 先采集输入规模、重复率与估算命中率，不改变执行逻辑
2. 灰度启用阶段
   - 先在高重复场景启用缓存，逐步扩大覆盖范围
3. 全量治理阶段
   - 建立统一的时效策略、容量上限、失效规则与回滚开关

### 验收标准

- 重复请求在可控时间窗内可稳定命中，且结果一致
- 输入消耗与平均响应时延出现可量化下降
- 具备命中率、节省量、失效率等核心监控指标
- 支持按场景快速开关，异常时可回退到无缓存模式
