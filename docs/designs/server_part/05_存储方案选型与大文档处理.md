  - ✅ 完全免费商用
  - ✅ 可作为托管服务提供
  - ✅ 可修改源码并分发
  - ✅ 无供应商锁定风险

#### PostgreSQL + pgvector
- **许可证类型**：PostgreSQL License（类BSD）
- **商业自由**：
  - ✅ 完全免费商用
  - ✅ 无任何使用限制
  - ✅ 可嵌入产品分发
  - ✅ pgvector 同样为 PostgreSQL License

### 2.2 部署说明

#### pgvector 是什么？
- **本质**：PostgreSQL 的扩展（extension），不是独立数据库
- **部署**：
  ```sql
  -- 在 PostgreSQL 实例中启用扩展
  CREATE EXTENSION vector;
  
  -- 创建向量字段
  CREATE TABLE documents (
      id SERIAL PRIMARY KEY,
      content TEXT,
      content_vector vector(1024)  -- pgvector 提供的类型
  );
  ```
- **运行方式**：无需单独部署进程，直接在 PG 内运行
- **注意事项**：
  - 云 RDS 需确认是否支持 pgvector 扩展
  - 自托管：需手动编译安装扩展（或用 Docker 镜像）

### 5.2 根据业务场景

**推荐**：PostgreSQL + pgvector
- ✅ 成本最低（单一数据库）
- ✅ 运维简单（团队已熟悉PG）
- ✅ ACID事务保证
- ⚠️ 接受中文召回略差（可通过自定义词典弥补）

#### 场景B：中型SaaS产品（100万-500万文档）
**推荐**：OpenSearch
- ✅ 无许可证风险（Apache 2.0）
- ✅ 性能优秀（接近ES）
- ✅ 中文分词好（安装IK插件）
- ✅ 水平扩展容易

#### 场景C：大型企业应用（>1000万文档）
**推荐**：Elasticsearch 或 OpenSearch
- ✅ 性能最强（亿级数据）
- ✅ 功能最全（聚合、高亮、复杂查询）
- ⚠️ ES需注意许可证（或选OpenSearch避免风险）

#### 场景D：私有化部署（客户内网）
**推荐**：PostgreSQL + pgvector
- ✅ 客户IT团队都会管PG
- ✅ 硬件要求低
- ✅ 售后成本低
- ✅ License定价空间大

## 六、session/skill 大文档处理方案

### 6.1 问题分析

#### 文档特征
- **类型**：session、skill（新增类型）
- **大小**：几MB 到几十MB
- **与现有差异**：
  - 现有（CODE/SCT/BUILD等）：按章节分块，每章节<10KB
  - 新增（session/skill）：单个文档可能>10MB

#### 核心挑战
1. **向量生成限制**：模型输入限制（512-8192 tokens），无法直接对几十MB文档生成单一向量
2. **数据库性能**：大文档直接存入ES/PG会拖垮查询性能
3. **检索粒度**：用户搜索时需要定位到文档内的具体部分，而非整个文档
4. **一致性风险**：文件系统 + 数据库双存储，可能不同步

### 6.2 推荐方案：分块存储（Chunking）

#### 架构设计

```
┌─────────────────────────────────────────────────┐
│  原始大文档（session-xxx.md, skill-yyy.md）     │
│  存储位置：文件系统 或 对象存储（S3/MinIO）      │
└─────────────────────────────────────────────────┘
                    ↓ 切分
┌─────────────────────────────────────────────────┐
│  文档块（Chunks）                                 │
│  - 每块 500-1000 tokens                         │
│  - 保留上下文（overlap 100 tokens）              │
│  - 记录在原文中的位置（offset）                   │
└─────────────────────────────────────────────────┘
                    ↓ 向量化
┌─────────────────────────────────────────────────┐
│  数据库记录（ES/PG/OpenSearch）                   │
│  - 每块一条记录                                   │
│  - 存储：块文本 + 块向量 + 元数据                  │
│  - 外键关联到文档主记录                           │
└─────────────────────────────────────────────────┘
```

### 6.3 数据模型设计

#### PostgreSQL + pgvector 实现

```sql
-- 文档主表（元数据）
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_type VARCHAR(20) NOT NULL,  -- 'session' 或 'skill'
    title TEXT NOT NULL,
    file_path TEXT NOT NULL,        -- 原文件路径
    file_size BIGINT,
    file_hash VARCHAR(64),          -- SHA256，检测文件变更
    summary TEXT,                   -- AI生成的摘要（可选）
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- 文档块表（检索单元）
CREATE TABLE document_chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,       -- 块序号（0, 1, 2, ...）
    chunk_text TEXT NOT NULL,       -- 块的文本内容
    chunk_vector vector(1024),      -- 块的向量
    chunk_tokens INT,               -- token数量
    start_offset INT,               -- 在原文中的起始字符位置
    end_offset INT,                 -- 在原文中的结束字符位置
    created_at TIMESTAMP DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_chunks_doc_id ON document_chunks(document_id);
CREATE INDEX idx_chunks_doc_type ON documents(doc_type);
CREATE INDEX idx_chunks_vector ON document_chunks 
    USING hnsw (chunk_vector vector_cosine_ops) 
    WITH (m = 16, ef_construction = 64);

-- 全文搜索索引（可选）
ALTER TABLE document_chunks ADD COLUMN chunk_tsv tsvector;
CREATE INDEX idx_chunks_tsv ON document_chunks USING GIN(chunk_tsv);

-- 自动更新全文索引触发器
CREATE TRIGGER tsvector_update BEFORE INSERT OR UPDATE
ON document_chunks FOR EACH ROW EXECUTE FUNCTION
tsvector_update_trigger(chunk_tsv, 'pg_catalog.chinese', chunk_text);
```

### 6.4 分块策略

#### 策略对比

| 策略 | 块大小 | 优点 | 缺点 | 适用场景 |
|------|--------|------|------|---------|
| **固定Token数** | 500-1000 tokens | 简单易实现 | 可能切断语义 | 通用 |
| **段落边界** | 按段落分割 | 语义完整 | 块大小不均 | 结构化文档 |
| **滑动窗口** | 500 tokens + 100 overlap | 避免边界丢失 | 冗余存储 | 需要上下文 |
| **语义分块** | 按主题分割（AI） | 语义最优 | 成本高、慢 | 高质量要求 |

#### 推荐实现（固定Token + 段落优化）

```python
from typing import List
import tiktoken

def chunk_document(
    text: str, 
    chunk_size: int = 600, 
    overlap: int = 100,
    encoding_name: str = "cl100k_base"
) -> List[dict]:
    """
    分块策略：优先按段落，超长段落再按token切分
    
    Args:
        text: 文档文本
        chunk_size: 目标块大小（tokens）
        overlap: 重叠区域大小（tokens）
        encoding_name: tiktoken 编码名称
    
    Returns:
        块列表，每块包含：text, tokens, start_offset, end_offset
    """
    encoding = tiktoken.get_encoding(encoding_name)
    paragraphs = text.split('\n\n')
    chunks = []
    current_chunk = ""
    current_tokens = 0
    current_offset = 0
    
    for para in paragraphs:
        para_tokens = len(encoding.encode(para))
        
        if current_tokens + para_tokens < chunk_size:
            # 当前段落可以加入当前块
            current_chunk += para + "\n\n"
            current_tokens += para_tokens
        else:
            # 保存当前块
            if current_chunk:
                chunk_text = current_chunk.strip()
                chunks.append({
                    "text": chunk_text,
                    "tokens": current_tokens,
                    "start_offset": current_offset,
                    "end_offset": current_offset + len(chunk_text)
                })
                current_offset += len(chunk_text)
            
            # 超长段落需要二次切分
            if para_tokens > chunk_size:
                sub_chunks = split_by_tokens(
                    para, 
                    chunk_size, 
                    overlap, 
                    encoding
                )
                for sub in sub_chunks:
                    chunks.append({
                        "text": sub,
                        "tokens": len(encoding.encode(sub)),
                        "start_offset": current_offset,
                        "end_offset": current_offset + len(sub)
                    })
                    current_offset += len(sub)
                current_chunk = ""
                current_tokens = 0
            else:
                # 开始新块
                current_chunk = para + "\n\n"
                current_tokens = para_tokens
    
    # 保存最后一个块
    if current_chunk:
        chunk_text = current_chunk.strip()
        chunks.append({
            "text": chunk_text,
            "tokens": current_tokens,
            "start_offset": current_offset,
            "end_offset": current_offset + len(chunk_text)
        })
    
    return chunks

def split_by_tokens(
    text: str, 
    chunk_size: int, 
    overlap: int, 
    encoding
) -> List[str]:
    """按 token 数切分超长段落（带重叠）"""
    tokens = encoding.encode(text)
    chunks = []
    
    for i in range(0, len(tokens), chunk_size - overlap):
        chunk_tokens = tokens[i:i + chunk_size]
        chunk_text = encoding.decode(chunk_tokens)
        chunks.append(chunk_text)
    
    return chunks
```

### 6.5 文档处理流程

#### 上传与索引

```python
from celery import shared_task
from uuid import uuid4
import hashlib
import os

async def upload_large_document(
    file: UploadFile, 
    doc_type: str,  # 'session' 或 'skill'
    title: str
):
    """
    大文档上传API
    
    Returns:
        {"document_id": "xxx", "status": "processing"}
    """
    # 1. 保存原文件到文件系统
    doc_id = str(uuid4())
    file_dir = f"/data/documents/{doc_type}/{doc_id[:2]}"
    os.makedirs(file_dir, exist_ok=True)
    file_path = f"{file_dir}/{doc_id}.md"
    
    content = await file.read()
    async with aiofiles.open(file_path, 'wb') as f:
        await f.write(content)
    
    # 2. 计算文件哈希
    file_hash = hashlib.sha256(content).hexdigest()
    
    # 3. 创建文档记录（PostgreSQL）
    doc = await db.execute(
        """
        INSERT INTO documents (id, doc_type, title, file_path, file_size, file_hash)
        VALUES ($1, $2, $3, $4, $5, $6)
        RETURNING id
        """,
        doc_id, doc_type, title, file_path, len(content), file_hash
    )
    
    # 4. 异步处理分块和向量化（不阻塞响应）
    process_large_document.delay(doc_id)
    
    return {"document_id": doc_id, "status": "processing"}


@shared_task
def process_large_document(document_id: str):
    """
    异步任务：分块 + 向量化
    """
    # 1. 读取文档信息
    doc = get_document(document_id)
    
    with open(doc['file_path'], 'r', encoding='utf-8') as f:
        content = f.read()
    
    # 2. 分块
    chunks = chunk_document(content, chunk_size=600, overlap=100)
    
    # 3. 批量生成向量（GPU加速）
    batch_size = 32
    all_vectors = []
    
    for i in range(0, len(chunks), batch_size):
        batch_texts = [c['text'] for c in chunks[i:i+batch_size]]
        batch_vectors = vector_model.encode(
            batch_texts, 
            batch_size=batch_size,
            show_progress_bar=False
        )
        all_vectors.extend(batch_vectors)
    
    # 4. 批量插入数据库（PostgreSQL）
    chunk_records = [
        (
            document_id,
            idx,
            chunk['text'],
            vector.tolist(),
            chunk['tokens'],
            chunk['start_offset'],
            chunk['end_offset']
        )
        for idx, (chunk, vector) in enumerate(zip(chunks, all_vectors))
    ]
    
    await db.executemany(
        """
        INSERT INTO document_chunks 
        (document_id, chunk_index, chunk_text, chunk_vector, 
         chunk_tokens, start_offset, end_offset)
        VALUES ($1, $2, $3, $4, $5, $6, $7)
        """,
        chunk_records
    )
    
    # 5. 更新文档状态
    await db.execute(
        "UPDATE documents SET updated_at = NOW() WHERE id = $1",
        document_id
    )
    
    logger.info(f"Processed document {document_id}: {len(chunks)} chunks")
```

```python
        """
        SELECT 
            c.id, c.document_id, c.chunk_text, c.chunk_index,
            c.start_offset, c.end_offset,
            1 - (c.chunk_vector <=> $1::vector) AS score
        FROM document_chunks c
        JOIN documents d ON c.document_id = d.id
        WHERE d.doc_type = $2
        ORDER BY c.chunk_vector <=> $1::vector
        LIMIT $3
        """,
        query_vector, doc_type, top_k * 3  # 先返回更多块
    )
    
    # 3. 按文档聚合并排序
    docs_dict = {}
    for chunk in chunks:
        doc_id = chunk['document_id']
        if doc_id not in docs_dict:
            docs_dict[doc_id] = {
                'chunks': [],
                'max_score': 0
            }
        
        docs_dict[doc_id]['chunks'].append({
            'text': chunk['chunk_text'],
            'score': chunk['score'],
            'index': chunk['chunk_index']
        })
        docs_dict[doc_id]['max_score'] = max(
            docs_dict[doc_id]['max_score'], 
            chunk['score']
        )
    
    # 4. 对每个文档，取Top-3最相关的块
    results = []
    for doc_id in sorted(docs_dict, key=lambda x: docs_dict[x]['max_score'], reverse=True)[:top_k]:
        doc = await get_document(doc_id)
        
        top_chunks = sorted(
            docs_dict[doc_id]['chunks'], 
            key=lambda x: x['score'], 
            reverse=True
        )[:3]
        
        results.append({
            "document": {
                "id": doc['id'],
                "title": doc['title'],
                "doc_type": doc['doc_type'],
                "file_path": doc['file_path'],  # 前端可下载完整文档
                "file_size": doc['file_size']
            },
            "matched_chunks": top_chunks,
            "score": docs_dict[doc_id]['max_score']
        })
    
    return results
```

### 6.6 一致性保证

#### 问题：文件与数据库不同步

**场景**：
- 文件被手动删除，但数据库记录还在
- 文件被修改，但向量未重新生成

**解决方案**：

```python
# 方案A：事务 + 回滚（推荐）
from contextlib import asynccontextmanager

@asynccontextmanager
async def atomic_file_db_operation():
    """原子的文件+数据库操作"""
    saved_files = []
    db_transaction = None
    
    try:
        db_transaction = await db.transaction()
        yield saved_files
        await db_transaction.commit()
    except Exception as e:
        # 回滚：删除已保存的文件
        for file_path in saved_files:
            if os.path.exists(file_path):
                os.remove(file_path)
        
        if db_transaction:
            await db_transaction.rollback()
        
        raise

# 使用示例
async def save_document_safely(file_path: str, metadata: dict):
    async with atomic_file_db_operation() as saved_files:
        # 保存文件
        shutil.copy(file_path, final_path)
        saved_files.append(final_path)
        
        # 插入数据库
        doc_id = await db.execute(
            "INSERT INTO documents (...) VALUES (...) RETURNING id",
            ...
        )


# 方案B：定期校验（后台任务）
@celery_app.task
def verify_file_db_consistency():
    """定期检查文件和数据库是否一致"""
    # 1. 检查孤立的数据库记录
    docs = await db.fetch("SELECT id, file_path, file_hash FROM documents")
    
    for doc in docs:
        if not os.path.exists(doc['file_path']):
            # 文件丢失，删除数据库记录
            await db.execute(
                "DELETE FROM documents WHERE id = $1",
                doc['id']
            )
            logger.warning(f"Deleted orphaned record: {doc['id']}")
        else:
            # 检查文件是否被修改
            current_hash = compute_file_hash(doc['file_path'])
            if current_hash != doc['file_hash']:
                # 文件已修改，重新索引
                process_large_document.delay(doc['id'])
                logger.info(f"Re-indexing modified document: {doc['id']}")
    
    # 2. 检查孤立的文件
    for file_path in glob.glob("/data/documents/**/*.md"):
        if not await db.fetchval(
            "SELECT 1 FROM documents WHERE file_path = $1",
            file_path
        ):
            # 数据库无记录，删除文件
            os.remove(file_path)
            logger.warning(f"Deleted orphaned file: {file_path}")
```

## 八、迁移路径建议

### 8.1 从 ES 迁移到 OpenSearch

**步骤**：

2. 安装 IK 分词插件（自托管）

### 8.2 从 ES 迁移到 PostgreSQL+pgvector

**难度**：🟡 中（需重构Repository层）

**步骤**：
1. 部署 PostgreSQL + 安装 pgvector 扩展
2. 创建表结构（documents + chunks）
3. 重写 Repository 层（从 ES DSL 改为 SQL）
4. 数据迁移脚本
5. 测试并调优（HNSW参数、查询性能）

**架构重构**：
```python
# 抽象层（保持不变）
class BaseSearchRepository(ABC):
    @abstractmethod
    async def search(self, query: str, filters: dict) -> List[dict]:
        pass

# 实现1：Elasticsearch
class ESSearchRepository(BaseSearchRepository):
    async def search(self, query, filters):
        # ES DSL 查询
        pass

# 实现2：PostgreSQL（新增）
class PGSearchRepository(BaseSearchRepository):
    async def search(self, query, filters):
        # SQL 查询
        query_vector = await self.vector_model.encode(query)
        
        results = await self.db.fetch("""
            SELECT * FROM document_chunks
            WHERE ...
            ORDER BY chunk_vector <=> $1
        """, query_vector)
        
        return results

# 工厂选择
if settings.storage_backend == "postgres":
    repository = PGSearchRepository()
else:
    repository = ESSearchRepository()
```

## 十、总结

### 10.1 关键结论

1. **许可证**：OpenSearch（Apache 2.0）和 PostgreSQL 完全免费商用，Elasticsearch 有限制
2. **中文分词**：ik_smart > OpenSearch+IK ≈ Elasticsearch > zhparser
3. **性能**：Elasticsearch ≈ OpenSearch >> PostgreSQL（大规模时）
4. **成本**：PostgreSQL < OpenSearch ≈ Elasticsearch
5. **大文档处理**：必须采用分块存储，三种方案都支持

### 10.2 session/skill 处理要点

- ✅ **必须分块**：500-1000 tokens/块，overlap 100 tokens
- ✅ **文件系统存原文**：数据库只存块 + 向量 + 元数据
- ✅ **一致性保证**：事务 + 定期校验
- ✅ **异步处理**：上传后立即返回，后台生成向量
