# v3 设计勘误与并发说明

本文档纠正 v3 配置管理设计中的问题，并说明多用户并发支持。

## 问题1：Celery 和 Redis 配置不能热更新

### ❌ v3 的错误说法

> "所有配置支持热更新：ES/Redis/向量模型/索引映射/业务配置"

### ✅ 实际情况

#### Celery 配置

**不能热更新，必须重启 worker**。

```python
# Celery worker 在启动时加载配置
celery -A app.infrastructure.celery.app worker --loglevel=info

# 如果修改了 broker_url 或 result_backend
# 必须重启 worker 才能生效
```

**原因**：
- Celery worker 启动时连接 broker（Redis）
- broker 连接在 worker 生命周期内保持
- 改配置需要重新建立连接 = 重启 worker

#### Redis 配置

**理论上可以重建连接，但不推荐**。

```python
# 虽然可以这样实现热更新
async def reconnect_redis():
    global _redis_client
    await _redis_client.close()  # 关闭旧连接
    _redis_client = await create_redis_client()  # 新连接
```

**不推荐的原因**：
1. 关闭连接会导致正在进行的操作失败
2. 可能丢失缓存数据
3. 客户端重连期间服务不可用
4. **风险大于收益**

#### Elasticsearch 配置

**同样不推荐热更新**，原因类似 Redis。

### ✅ 正确的配置分类

| 配置类型 | 热更新 | 生效方式 |
|----------|--------|----------|
| **Elasticsearch** | ❌ | 重启应用 |
| **Redis** | ❌ | 重启应用 |
| **Celery** | ❌ | 重启 worker |
| **向量模型列表** | ✅ | API 重载 |
| **搜索参数** | ✅ | API 重载 |
| **上传配置** | ✅ | API 重载 |

## 问题2：索引映射不能通过配置动态应用

### ❌ v3 的错误理解

我在 v3 中说"Repository 从配置读取映射并应用到查询"，这是**错误**的。

### ✅ 实际情况

#### 索引映射的生命周期

```
1. 创建索引时定义映射
   └─> 映射固定，不能修改

2. 查询时使用已有映射
   └─> 从 ES 读取，不是从配置文件
```

#### 映射不可变性

```python
# ✅ 创建索引时设置映射
await es.indices.create(
    index="my_index",
    body={
        "mappings": {
            "properties": {
                "content": {"type": "text", "analyzer": "ik_max_word"},
                "vector": {"type": "dense_vector", "dims": 1024}
            }
        }
    }
)

# ❌ 不能修改已有索引的映射
# 如果需要修改，必须：
# 1. 创建新索引（新映射）
# 2. 重新导入数据（reindex）
# 3. 删除旧索引
```

### ✅ 配置文件的正确用途

配置文件中的映射**只用于创建新索引的模板**：

```yaml
# config/dynamic_config.yaml
index_mappings:
  CODE:  # 这是创建索引时的模板
    properties:
      content:
        type: text
        analyzer: ik_max_word        # ✅ 使用中文分词
      language:
        type: keyword
      vector:
        type: dense_vector
        dims: 1024
```

```python
# features/search/repositories/code.py
class CodeSearchRepository:
    async def create_index_if_not_exists(self, index_name: str):
        """创建索引（使用配置的模板）"""
        if await self.es.indices.exists(index=index_name):
            logger.info(f"Index already exists: {index_name}")
            return
        
        # ✅ 从配置读取映射模板
        config = get_config_manager()
        mapping_template = config.get_index_mapping("CODE")
        
        # 创建索引
        await self.es.indices.create(
            index=index_name,
            body={
                "mappings": mapping_template,
                "settings": config.get_index_settings("CODE")
            }
        )
    
    async def search(self, index_name: str, query: str):
        """查询时不需要映射（ES 已经知道）"""
        # ✅ 直接查询，ES 使用索引创建时的映射
        result = await self.es.search(
            index=index_name,
            body={"query": {"match": {"content": query}}}
        )
        return result
```

### ⚠️ 与现有代码的差异

您现有代码是**正确的**：

```python
# x_logic/import_logic_coding_standards.py
def _get_index_mapping(use_vector: bool = False, vector_dims: int = None) -> dict:
    mapping = {
        "mappings": {
            "properties": {
                "chapter_title": {
                    "type": "text",
                    "analyzer": "ik_max_word",  # ✅ 中文分词
                    "search_analyzer": "ik_smart"
                },
                # ... 其他字段
            }
        }
    }
    
    # ✅ 根据 use_vector 动态添加向量字段
    if use_vector and vector_dims:
        mapping["mappings"]["properties"]["content_vector"] = {
            "type": "dense_vector",
            "dims": vector_dims,
            "index": True,
            "similarity": "cosine"
        }
    
    return mapping
```

**v3 改进建议**：配置文件应该和现有代码保持一致：

```yaml
# config/dynamic_config.yaml
index_mappings:
  CODING_STANDARDS:
    properties:
      language:
        type: keyword
      chapter_title:
        type: text
        analyzer: ik_max_word        # ✅ 保持现有的中文分词
        search_analyzer: ik_smart
      rules:
        type: text
        analyzer: ik_max_word
        search_analyzer: ik_smart
      rules_list:
        type: text
        index: false
      # 向量字段在代码中动态添加，不在配置中固定
```

## 问题3：多用户并发支持

### ✅ FastAPI 天然支持高并发

#### 并发模型

```python
# FastAPI 基于 asyncio 的异步并发模型

# 请求1: 用户A 搜索"async"
async def search_request_1():
    result = await search_service.search(...)  # 协程1
    return result

# 请求2: 用户B 搜索"FastAPI"
async def search_request_2():
    result = await search_service.search(...)  # 协程2
    return result

# ✅ 两个请求同时处理，互不阻塞
# 当协程1等待ES响应时，协程2可以执行
# 没有线程切换开销，性能高效
```

#### 请求隔离

每个请求都是**完全独立**的：

```python
@router.post("/search")
async def search_endpoint(
    request: SearchRequest,                    # ✅ 每个请求独立的参数
    service: SearchService = Depends(...)      # ✅ 每次调用创建新实例
):
    # ✅ 局部变量，请求之间不共享
    result = await service.search(request)
    return result
```

#### 共享资源的线程安全

```python
# ES 客户端：线程安全
_es_client = AsyncElasticsearch(...)  # ✅ 内部使用连接池

# Redis 客户端：线程安全
_redis_client = aioredis.Redis(...)   # ✅ 内部使用连接池

# 配置管理器：使用锁保护
class ConfigManager:
    def __init__(self):
        self._lock = threading.RLock()  # ✅ 线程安全锁
    
    def get(self, key: str):
        with self._lock:                # ✅ 读取时加锁
            return self._config.get(key)
```

```python
import asyncio
import pytest

@pytest.mark.asyncio
async def test_concurrent_searches():
    """测试多个搜索请求并发执行"""
    
    # 创建100个并发搜索请求
    tasks = []
    for i in range(100):
        task = search_service.search(
            SearchRequest(
                keyword=f"test_{i}",
                doc_type="CODE",
                index="test_index"
            )
        )
        tasks.append(task)
    
    # ✅ 并发执行所有请求
    results = await asyncio.gather(*tasks)
    
    # 验证结果
    assert len(results) == 100
    
    # 验证每个结果都是独立的
    for i, result in enumerate(results):
        # 每个结果应该对应各自的查询
        assert f"test_{i}" in str(result)
```

### 性能特征

| 指标 | FastAPI 异步 | 传统同步 |
|------|-------------|----------|
| **并发模型** | 协程（轻量） | 线程/进程（重量） |
| **内存占用** | 低（每个请求 ~KB） | 高（每个线程 ~MB） |
| **并发数量** | 数千 | 数百 |
| **响应时间** | 快（无上下文切换） | 慢（线程切换开销） |
| **资源利用** | 高（CPU密集时） | 一般 |

## 修正后的配置分类

### 1. 静态配置（settings.py）- 启动时加载

```python
# config/settings.py
class Settings(BaseSettings):
    # 应用基础
    app_name: str = "Document Search API"
    version: str = "3.0.0"
    
    # ⚠️ 这些需要重启才能生效

    # 配置文件路径
```

## 总结

### 修正的关键点

1. **Celery/Redis/ES 配置不能热更新**
   - 需要重启应用或 worker
   - 放在静态配置中

2. **索引映射不能动态应用**
   - 索引创建后映射固定
   - 配置文件只是创建模板
   - 应使用 ik_max_word 分词器（中文）

3. **并发支持完全没问题**
   - FastAPI 异步并发
   - 每个请求独立
   - 共享资源线程安全
   - 支持数千并发

### 推荐的配置策略

```
启动配置（需重启）：
  - ES/Redis/Celery 连接信息
  - 应用基础信息

运行时配置（可热更新）：
  - 业务参数（搜索、上传）
  - 向量模型列表
  - 索引映射模板（仅用于新索引）

完全动态（无需配置）：
  - 用户请求参数
  - 查询关键词
  - 文件上传
```
